    1. Visão geral e pré-requisitos

    Antes de instalar qualquer componente, confirme compatibilidade, direitos administrativos e dependências do Windows.

    1.1 Requisitos mínimos

    • Windows 11 ou Windows 10 versão 2004+ com build 19041 ou superior.
    • Permissão de administrador local para ativar recursos do Windows.
    • Conexão com internet estável para baixar WSL, Ubuntu e Google Chrome.
    • Pelo menos 15 GB livres em disco; 30 GB é mais confortável para desenvolvimento.
    • Virtualização habilitada na BIOS/UEFI: Intel VT-x ou AMD-V.

    1.2 O que será instalado

    • Subsistema Windows para Linux (WSL).
    • Motor de virtualização do WSL 2.
    • Distribuição Ubuntu.
    • Google Chrome para Linux dentro do Ubuntu.
    • Base recomendada para IA: Python, pip, venv, Git e VS Code.
    Reavaliação do cenário: para Engenharia de IA, usar WSL 2 é essencial. O WSL 1 é mais simples, mas perde compatibilidade com várias bibliotecas Linux, containers e fluxos modernos de desenvolvimento.

    1.3 Verificações iniciais no Windows

    1. Abra o menu Iniciar, pesquise por PowerShell, clique com o botão direito e selecione Executar como administrador.
    2. Confirme a versão do Windows executando o comando abaixo. Compare o número da build com o requisito mínimo.
    3. Verifique se a virtualização está ativa pelo Gerenciador de Tarefas em Desempenho > CPU > Virtualização.
    4. Confirme se você tem espaço livre em disco em Configurações > Sistema > Armazenamento.
    5. Se o computador for corporativo, confirme se políticas de segurança não bloqueiam recursos opcionais, Microsoft Store ou instalação de software.
    PowerShell (Administrador) 
    winver
systeminfo | findstr /B /C:"OS Name" /C:"OS Version"

    2. Configurações detalhadas no Windows

    Esta etapa cobre tudo o que precisa ser ajustado no sistema operacional antes ou durante a instalação do WSL.

    2.1 Atualizar o Windows

    1. Acesse Configurações > Windows Update.
    2. Clique em Verificar se há atualizações.
    3. Instale todas as atualizações importantes, inclusive as cumulativas.
    4. Reinicie o computador se solicitado.
    5. Repita a checagem até não haver pendências críticas.

    2.2 Ativar virtualização na BIOS/UEFI

    1. Reinicie o computador e entre no setup da BIOS/UEFI usando a tecla indicada pelo fabricante, como F2, Del ou Esc.
    2. Procure opções com nomes como Intel Virtualization Technology (VT-x), Intel VT-d, SVM Mode ou AMD-V.
    3. Ative a opção correspondente.
    4. Salve as alterações e saia.
    5. Ao voltar ao Windows, confirme a ativação pelo Gerenciador de Tarefas.
    Possível erro: se a opção de virtualização não aparecer, o firmware pode estar desatualizado, bloqueado por política corporativa ou o processador pode não oferecer suporte adequado. Nesses casos, consulte o fabricante da máquina.

    2.3 Ativar recursos opcionais do Windows manualmente

    Mesmo usando wsl --install, é útil conhecer a ativação manual caso a instalação simplificada falhe.

    PowerShell (Administrador) 
    dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
    1. Execute os comandos acima em um PowerShell com privilégios administrativos.
    2. Reinicie o computador quando a ativação terminar.
    3. Depois do reinício, volte ao PowerShell e prossiga com a instalação do WSL.

    2.4 Método gráfico alternativo

    1. Abra o menu Iniciar e pesquise por Ativar ou desativar recursos do Windows.
    2. Marque Subsistema do Windows para Linux.
    3. Marque Plataforma de Máquina Virtual.
    4. Confirme, aguarde a instalação e reinicie o sistema.

    3. Instalação do WSL e do Ubuntu

    Agora o ambiente Linux será efetivamente instalado.

    3.1 Instalação simplificada

    PowerShell (Administrador) 
    wsl --install
wsl --set-default-version 2
    1. Execute wsl --install. O Windows instalará os componentes necessários e, em muitos casos, o Ubuntu padrão.
    2. Se solicitado, reinicie o computador.
    3. Depois do reboot, a instalação do Ubuntu pode continuar automaticamente.
    4. Quando a janela do Ubuntu abrir, crie seu usuário Linux e uma senha forte.
    5. Guarde essa senha: ela será usada com sudo para instalar pacotes e alterar configurações.

    3.2 Instalação explícita do Ubuntu

    Se o Ubuntu não vier automaticamente ou se você quiser escolher a distribuição manualmente:

    PowerShell (Administrador) 
    wsl --list --online
wsl --install -d Ubuntu

    3.3 Confirmar status do WSL

    PowerShell ou CMD 
    wsl --status
wsl --list --verbose
    Validação Resultado esperado Ação se estiver diferente
    wsl --status WSL instalado e versão padrão 2 Execute wsl --set-default-version 2 e revise os recursos do Windows.
    wsl --list --verbose Ubuntu em estado Running ou Stopped e versão 2 Se estiver em versão 1, use wsl --set-version Ubuntu 2.

    3.4 Primeiro acesso ao Ubuntu

    Bash (Ubuntu no WSL) 
    uname -a
lsb_release -a
whoami
pwd
    Boa prática: os arquivos do projeto Linux devem ficar preferencialmente dentro do sistema de arquivos do WSL, por exemplo em /home/seu_usuario/projetos. Isso melhora desempenho e reduz problemas de permissões.

    4. Atualização do Ubuntu e instalação do Google Chrome

    Com o Ubuntu inicializado, atualize o sistema e instale o navegador.

    4.1 Atualizar pacotes básicos

    Bash (Ubuntu) 
    sudo apt update
sudo apt upgrade -y
sudo apt install -y wget curl ca-certificates gnupg software-properties-common
    1. Abra o Ubuntu pelo menu Iniciar ou com wsl.
    2. Execute os comandos acima para atualizar os repositórios e os pacotes instalados.
    3. Instale utilitários necessários para o download e validação do pacote do Chrome.

    4.2 Instalar o Google Chrome no Ubuntu

    Bash (Ubuntu) 
    wget https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
sudo apt install -y ./google-chrome-stable_current_amd64.deb

    Se o APT indicar dependências pendentes, execute:

    Bash (Ubuntu) 
    sudo apt --fix-broken install -y

    4.3 Executar o Chrome no WSL

    Bash (Ubuntu) 
    google-chrome
# ou, em alguns ambientes:
google-chrome-stable
    WSLg: em Windows 11 e instalações atualizadas do WSL, aplicações gráficas Linux funcionam com WSLg. Isso permite abrir o Chrome do Ubuntu com interface gráfica sem instalar servidor X externo na maioria dos casos.
    Atenção: em máquinas corporativas ou ambientes sem WSLg, o Chrome pode não abrir por falta de suporte gráfico. Nessa situação, atualize o WSL, reinicie o serviço e valide se a sessão Linux possui integração gráfica habilitada.

    5. Troubleshooting durante a instalação

    A tabela abaixo reúne falhas comuns e as ações corretivas mais úteis.

    Erro ou sintoma Causa provável Solução detalhada
    “WslRegisterDistribution failed with error: 0x80370102” Virtualização desabilitada ou recurso de plataforma virtual não ativo. Ative Intel VT-x/AMD-V na BIOS, confirme Plataforma de Máquina Virtual no Windows e reinicie. Depois execute wsl --status.
    “The requested operation requires elevation” Comando executado sem privilégios administrativos. Feche a janela atual, abra PowerShell como administrador e rode novamente o comando de instalação.
    Ubuntu abre e fecha imediatamente Instalação incompleta, atualização pendente ou corrupção da distro. Rode wsl --shutdown, atualize o WSL com wsl --update e tente abrir a distro novamente. Se persistir, exporte dados importantes e reinstale a distro.
    Chrome não abre no Ubuntu WSLg desatualizado, dependências quebradas ou ausência de suporte gráfico. Atualize com wsl --update, execute sudo apt --fix-broken install -y e reinicie a sessão com wsl --shutdown. Depois abra o Ubuntu e teste novamente.
    Erro de download do pacote .deb Rede corporativa, proxy, DNS ou bloqueio de URL. Teste a conectividade com curl -I https://dl.google.com, configure proxy se necessário e tente outra rede. Em ambiente corporativo, consulte a TI.
    Sem espaço em disco Armazenamento insuficiente no Windows ou na VHD do WSL. Libere espaço, remova distros não usadas e reinicie. Para casos avançados, considere mover a distro ou revisar políticas de armazenamento.

    5.1 Comandos úteis para correção

    PowerShell 
    wsl --update
wsl --shutdown
wsl --status
wsl --list --verbose
    Bash (Ubuntu) 
    sudo apt update
sudo apt --fix-broken install -y
sudo dpkg --configure -a
    Cuidado: só use wsl --unregister Ubuntu se você tiver certeza de que não precisa dos dados da distribuição. Esse comando remove a distro e seus arquivos locais.

    6. Boas práticas para Engenharia de IA no WSL

    Após instalar o ambiente, vale estruturá-lo corretamente para produtividade, reprodutibilidade e desempenho.

    6.1 Pacotes-base recomendados

    Bash (Ubuntu) 
    sudo apt install -y python3 python3-pip python3-venv git build-essential unzip

    6.2 Python e ambientes virtuais

    1. Crie uma pasta de projetos dentro do Linux, por exemplo ~/projetos.
    2. Para cada projeto, crie um ambiente virtual dedicado.
    3. Mantenha dependências em requirements.txt ou em um gerenciador equivalente.
    4. Evite instalar bibliotecas globais no sistema quando o objetivo for desenvolvimento repetível.
    Bash (Ubuntu) 
    mkdir -p ~/projetos/exemplo-ia
cd ~/projetos/exemplo-ia
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip

    6.3 VS Code e integração com WSL

    • Instale o VS Code no Windows.
    • Adicione a extensão WSL.
    • Abra o terminal Ubuntu e execute code . dentro da pasta do projeto.
    • Prefira editar projetos Linux a partir do lado Linux para melhor desempenho.

    6.4 Git e organização do trabalho

    Bash (Ubuntu) 
    git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

    6.5 Ajustes de desempenho com .wslconfig

    Se você usa modelos, notebooks e bibliotecas mais pesadas, limitar recursos do WSL ajuda a manter equilíbrio com o Windows.

    Arquivo no Windows: %UserProfile%\.wslconfig 
    [wsl2]
memory=8GB
processors=4
swap=4GB
localhostForwarding=true
    1. Crie o arquivo .wslconfig no diretório do seu usuário Windows, por exemplo C:\Users\SeuUsuario\.wslconfig.
    2. Salve os parâmetros de memória, CPU e swap conforme a capacidade da máquina.
    3. Aplique as mudanças com wsl --shutdown e reabra o Ubuntu.

    6.6 Chrome, WSLg e produtividade

    • Use o Chrome do Ubuntu quando quiser testar aplicações Linux com ambiente gráfico nativo do WSL.
    • Para uso cotidiano simples, o navegador Windows pode continuar sendo suficiente.
    • Evite múltiplas abas pesadas no WSL em máquinas com pouca RAM.
    • Se for usar automação com navegador, mantenha versões do Chrome e bibliotecas compatíveis.

    7. Checklist de validação final

    Use a lista abaixo para garantir que a instalação terminou corretamente.

    • O Windows está atualizado e reiniciado após as alterações necessárias.
    • A virtualização está ativa no firmware e confirmada no Windows.
    • Os recursos Subsistema do Windows para Linux e Plataforma de Máquina Virtual estão ativos.
    • O comando wsl --status executa sem erro.
    • O Ubuntu foi iniciado e o usuário Linux foi criado com sucesso.
    • O comando wsl --list --verbose mostra a distro Ubuntu na versão 2.
    • Os comandos sudo apt update e sudo apt upgrade -y terminaram sem erro crítico.
    • O Google Chrome foi instalado no Ubuntu e abre com interface gráfica.
    • Python, pip, venv e Git estão disponíveis no Ubuntu.
    • Projetos de IA serão salvos dentro do sistema de arquivos Linux para melhor desempenho.
    • Se necessário, o arquivo .wslconfig foi criado e aplicado com recursos ajustados.
    Conclusão esperada: ao final deste checklist, você terá um ambiente Windows + Ubuntu via WSL pronto para navegação gráfica, desenvolvimento Python, uso de Git e evolução para fluxos de Engenharia de IA mais completos.

    8. Apêndice: erros comuns do WSL

    Referência rápida para problemas recorrentes após a instalação.

    Mensagem / situação Interpretação Resposta recomendada
    0x800701bc Kernel do WSL ausente ou desatualizado. Execute wsl --update e reinicie a sessão com wsl --shutdown.
    0x80070003 Caminho, pacote ou registro da distribuição inconsistente. Atualize o WSL, revise a instalação da distro e valide se não houve remoção manual de arquivos.
    0xffffffff Falha genérica do subsistema, muitas vezes ligada a serviço parado ou corrupção. Reinicie com wsl --shutdown, reinicie o Windows e teste novamente. Se persistir, investigue eventos e reinstale a distro.
    Erro de DNS no Ubuntu Integração de rede do WSL ou políticas corporativas interferindo. Teste conectividade, revise VPN/proxy e, se necessário, ajuste DNS com suporte da TI.
    Lentidão excessiva no acesso a arquivos Projeto sendo executado em unidade Windows montada em vez de diretório Linux. Mova o projeto para /home/usuario ou outra pasta interna do WSL.
    Permissões estranhas em arquivos Git Mistura de edição entre ferramentas Windows e Linux no mesmo diretório montado. Padronize a edição pelo lado Linux com VS Code Remote WSL e revise permissões do projeto.
